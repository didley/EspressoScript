CLI Reference

shot

The shot command orchestrates the full pipeline: lint → type-check → execute. Type errors block execution — the program never runs if shot check fails.

$ curl -fsSL https://shot.didley.dev/install.sh | sh
shot init
shot init <name>

Scaffold a new project directory with a .shot entry file, a test file, and a shot.json config stub.

# scaffold a new project
$ shot init my-app
shot check
shot check [files...]

Validate one or more .shot files. Runs the linter only — does not type-check, does not run. If no files are given, checks all .shot files in the current directory.

src/main.shot:3:5  no-arrow-functions  Arrow functions are not allowed.
0no diagnostics
1at least one diagnostic emitted
2internal error
$ shot check src/main.shot
$ shot check src/**/*.shot
shot fmt
shot fmt [files...]

Format .shot files in place. Zero config — one canonical output. If no files are given, formats the current directory recursively.

$ shot fmt src/main.shot
$ shot fmt src/
shot build
shot build [files...]

Validate → type-check. Does not execute. Runs the linter, then type-checks via the TypeScript compiler. Aborts on any diagnostic.

No emitted .ts files; build is purely a validation gate.

$ shot build src/main.shot
shot run
shot run <file> [-- flags...]

Validate → type-check → execute. The program never runs if lint or type-check fails. Flags after -- pass through to Bun.

0program exited cleanly
1lint or type-check failed — program did not run
2internal error
$ shot run hello.shot
$ shot run hello.shot -- --port 3000
shot test
shot test [files...]

Validate → type-check → run *.test.shot files. If no files are given, finds all *.test.shot in the current directory.

$ shot test
$ shot test src/calculator.test.shot

All commands return exit 0 on success, non-zero on any failure (lint, type-check, or runtime).
