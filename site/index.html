TypeScript,

Shot extracts features from TypeScript — applying Go's "one canonical way" philosophy to the TS/JS ecosystem. One form per construct, enforced by the linter. Easier for humans to review. Easier for LLMs to generate correctly.

The problem

Too many ways to write the same thing.

TypeScript lets you declare variables three ways, write functions four ways, handle errors five ways. Reading unfamiliar code is hard. Code review is harder. LLM-assisted generation amplifies every inconsistency — more valid forms means more ways to generate subtly wrong code.

shot's answer: a strict lint pass that enforces one canonical form. Every .shot file is valid TypeScript — so the full Deno ecosystem, type system, and tooling work unchanged. We maintain a list of rules, not a compiler.
no-throw / no-try
Errors are values — return ShotPromise<T, E> tuples. Failure is in the type signature, not the air.
no-undefined-type / no-optional-property
null is the only absent value. No ?, no | undefined — one way to say "nothing."
require-readonly-property / require-readonly-arrays
Every field and array is readonly by default. Mutation is opt-in and explicit.
no-any / no-assertion / no-non-null
Type safety is not optional. any, as, !, and @ts-ignore are all banned.
no-class / no-this
Plain type + plain functions. No hidden state, no inheritance, no this.
no-arrow-functions
Every function is named and grep-able. Callbacks become testable, findable units.
no-interface / no-enum
One way to define a shape: type. No parallel declaration syntax.
no-ternary
If/else forces names onto branches. Nesting disappears.

Error handling

TypeScript
async function getUser(
  id: number
): Promise<User> {
  try {
    const res = await fetch(`/users/${id}`)
    if (!res.ok) throw new Error(
      `HTTP ${res.status}`
    )
    return res.json() as User
  } catch (e) {
    throw new Error(`getUser failed: ${e}`)
  }
}
shot
import { fetch, jsonParse } from "shot:std"
import type { ShotPromise } from "shot:std"

async function getUser(
  id: number
): ShotPromise<User> {
  const [res, err] = await fetch(`/users/${id}`)
  if (err !== null) {
    return [null, err]
  }
  return jsonParse<User>(await res.text())
}

// no throw · no try · no hidden control flow
Why it matters: thrown exceptions don't appear in function signatures. Callers have no idea a function can fail without reading its source — or its documentation, if any exists. ShotPromise<T, E> makes every failure path explicit in the type, enforced by the checker.

Custom error types

TypeScript
class ApiError extends Error {
  statusCode: number
  constructor(msg: string, code: number) {
    super(msg)
    this.statusCode = code
  }
}

async function getUser(
  id: number
): Promise<User> {
  const res = await fetch(`/users/${id}`)
  if (!res.ok) throw new ApiError(
    "not found", res.status
  )
  return res.json() as User
}

// caller doesn't know this throws
shot
type ApiError = {
  readonly message: string
  readonly statusCode: number
}

async function getUser(
  id: number
): ShotPromise<User, ApiError> {
  const [res, err] = await fetch(`/users/${id}`)
  if (err !== null) {
    return [null, { message: err.message, statusCode: 500 }]
  }
  if (!res.ok) {
    return [null, { message: "not found", statusCode: res.status }]
  }
  return jsonParse<User>(await res.text())
}

// caller sees ApiError in the signature
No class hierarchy needed. Custom error shapes are plain type declarations — no extends, no constructor, no this. The error type E in ShotPromise<T, E> can be anything: a plain type, or a discriminated union when a function has multiple failure modes. To add context when propagating, use wrapError(message, cause) from shot:std — the shot equivalent of Go's fmt.Errorf("context: %w", err).

Absent values

TypeScript
// three ways to say "nothing"
type User = {
  id: number
  avatar?: string
  deletedAt?: Date
}

function findUser(
  id?: number
): User | undefined { /* ... */ }
shot
// one way — null is the only absent value
type User = {
  readonly id: number
  readonly avatar: string | null
  readonly deletedAt: Date | null
}

function findUser(
  id: number
): [User | null, Error | null] { /* ... */ }
Why it matters: TypeScript has three ways to express "this might not exist" — ?, | undefined, and | null — and most codebases mix all three. shot picks one: null. Every optional field is T | null, every fallible return is [T | null, Error | null]. No more checking for both.

Type complexity

TypeScript
// intersection to "extend" a base type
type User = {
  readonly id: number
  readonly name: string
}

type AdminUser =
  User & { readonly role: 'admin' }

// what fields does AdminUser have?
// depends on what User is today
shot
// embed as a named field — Go/Rust-style
type User = {
  readonly id: number
  readonly name: string
}

type AdminUser = {
  readonly user: User
  readonly role: 'admin'
}

// access: admin.user.id
Why it matters: intersection types hide fields behind indirection — to know what AdminUser actually contains you have to trace every component. shot bans &, conditional types, mapped types, and infer. Instead of extending, embed: give the base type a named field. Every shape is self-contained and readable where it's defined.

Immutable by default

TypeScript
type Config = {
  host: string
  port: number
}

const ids: number[] = []

// any function can mutate these
// nothing in the types stops it
shot
type Config = {
  readonly host: string
  readonly port: number
}

const ids: ReadonlyArray<number> = []

// compiler rejects any write to these
Why it matters: mutable data structures mean any function, at any call site, can change state you didn't expect. readonly and ReadonlyArray make the compiler enforce immutability — mutation becomes opt-in, visible, and intentional.

Data + behaviour

TypeScript
class UserService {
  private readonly db: Database

  constructor(db: Database) {
    this.db = db
  }

  async findById(
    id: number
  ): Promise<User | null> {
    // ...
  }
}

const svc = new UserService(db)
shot
type UserService = { readonly db: Database }

async function findUserById(
  svc: UserService,
  id: number,
): Promise<[User | null, Error | null]> {
  // ...
}

const svc: UserService = { db }
Why it matters: a type is data. A function is behaviour. There is no hidden state, no inheritance graph to trace, no this context to reason about. Both are independently testable.

Callbacks

TypeScript
const total = items
  .filter(x => x.active)
  .map(x => ({ ...x, score: x.score * 2 }))
  .reduce((acc, x) => acc + x.score, 0)

// inline logic · untestable · no names to grep
shot
function isActive(item: Item): boolean {
  return item.active
}
function doubleScore(item: Item): Item {
  return { ...item, score: item.score * 2 }
}
function sumScore(acc: number, item: Item): number {
  return acc + item.score
}

const total = items
  .filter(isActive)
  .map(doubleScore)
  .reduce(sumScore, 0)
Why it matters: named functions are testable in isolation, searchable with grep, and show up in stack traces. Anonymous arrow callbacks disappear the moment they fail.

Conditionals

TypeScript
const label = isAdmin
  ? (isSuperAdmin ? "Super Admin" : "Admin")
  : "User"

// nesting grows with every new role
shot
function roleLabel(
  isAdmin: boolean,
  isSuperAdmin: boolean,
): string {
  if (isSuperAdmin) {
    return "Super Admin"
  }
  if (isAdmin) {
    return "Admin"
  }
  return "User"
}
Why it matters: each branch has a name. Adding a new role means adding a clause, not untangling a nested expression. The complexity stays flat.
Tooling

One command, four verbs.

shot's pipeline mirrors Go's: lint → type-check → run. The program never executes if the types are wrong.

terminal
# scaffold a project
$ shot init my-app

# type-check and lint
$ shot check src/

# format — zero config, one canonical output
$ shot fmt

# run (lint → check → execute)
$ shot run src/main.shot

# test (lint → check → run *.test.shot)
$ shot test
Live example

A working todo app.

Full CRUD — add, complete, delete. The logic runs directly from the compiled .shot source on the left.

todo.shot
import { mutableRef, wrapError } from "shot:std"

type Todo = {
  readonly id: number
  readonly title: string
  readonly done: boolean
}

const _todos = mutableRef<readonly Todo[]>([])
const _nextId = mutableRef(1)

export function addTodo(title: string): [Todo | null, Error | null] {
  const trimmed = title.trim()
  if (trimmed.length === 0) {
    return [null, new Error("title must not be empty")]
  }
  const todo: Todo = { id: _nextId.value, title: trimmed, done: false }
  _nextId.value = _nextId.value + 1
  _todos.value = [..._todos.value, todo]
  return [todo, null]
}

export function toggleTodo(id: number): [Todo | null, Error | null] {
  const [found, findErr] = findById(id)
  if (findErr !== null) return [null, wrapError(`toggle ${id}`, findErr)]
  // ...
}

export function removeTodo(id: number): [null, Error | null] {
  const [_found, findErr] = findById(id)
  if (findErr !== null) return [null, wrapError(`remove ${id}`, findErr)]
  _todos.value = _todos.value.filter(
    function keepOthers(t) { return t.id !== id }
  )
  return [null, null]
}
