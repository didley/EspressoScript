Language Reference

Shot language rules

Every rule below is enforced by shot check. Violations exit non-zero with a diagnostic. Rules apply to both .shot files (ShotScript) and TypeScript files linted with ShotLint.

Functions

no-arrow-functions

Arrow functions are banned. Use named function declarations or expressions — they show up in stack traces, are grep-able, and testable in isolation.

❌
const greet = (name: string) => `hello ${name}`
[1, 2].map((n) => n * 2)
✅
function greet(name: string): string {
  return `hello ${name}`
}
[1, 2].map(function double(n: number): number {
  return n * 2
})

require-explicit-return-type

Every function declaration must have an explicit return type. Inference hides contracts from readers and lets return-type drift go unnoticed.

❌
function double(n: number) { return n * 2 }
✅
function double(n: number): number { return n * 2 }

require-named-functions

Function expressions passed as arguments must be named. Anonymous callbacks produce useless (anonymous) stack frames.

❌
[1, 2].map(function(n: number): number { return n * 2 })
✅
[1, 2].map(function double(n: number): number { return n * 2 })

Variables

no-var / no-let-outside-for

var is banned. let is only allowed inside for loop headers. Everywhere else: const. For mutable module-level state, use a plain const object: const state = { value: 0 }.

❌
let x = 1
var y = 2
✅
const x = 1
for (let i = 0; i < 10; i += 1) { /* ok */ }

no-increment-decrement

++ and -- are banned. Use += 1 and -= 1.

Error handling

The core pattern: errors are values. Fallible functions return [T | null, Error | null]. The caller destructures and checks. No hidden control flow. PromiseResult<T, E> is the canonical alias for async fallible functions.

no-throw / no-try

Throwing and try/catch are banned. Return errors as values instead.

❌
async function getUser(id: number): Promise<User> {
  try {
    const res = await fetch(`/users/${id}`)
    return res.json() as User
  } catch (e) {
    throw new Error(`failed: ${e}`)
  }
}
✅
import { safeFetch, jsonParse } from "shot:std"
import type { PromiseResult } from "shot:std"

async function getUser(id: number): PromiseResult<User> {
  const [res, err] = await safeFetch(`/users/${id}`)
  if (err !== null) { return [null, err] }
  return jsonParse<User>(await res.text())
}

Custom error types

Error shapes are plain type declarations — no class hierarchy. Use a discriminated union for multiple failure modes. 

type AppError =
  | { readonly kind: "network"; readonly status: number }
  | { readonly kind: "parse"; readonly input: string }

async function load(id: number): PromiseResult<User, AppError> { /* ... */ }

Wrapping throwing APIs

Use toResult (sync) or toPromiseResult (async) from shot:std to wrap external APIs that throw. 

import { toResult, toPromiseResult } from "shot:std"

const [parsed, err] = toResult(() => someLib.parseSync(input))
const [rows, err] = await toPromiseResult(() => db.query(sql))

Types

no-interface — type only

One way to define a shape: type. Interfaces are banned.

❌
interface User { id: number }
✅
type User = { readonly id: number }

no-enum — as const instead

❌
enum Direction { Up, Down }
✅
const Direction = { Up: "up", Down: "down" } as const
type Direction = typeof Direction[keyof typeof Direction]

no-class / no-this

Classes and this are banned. Use a plain type for data, plain functions for behaviour.

❌
class UserService {
  constructor(db: Database) { this.db = db }
}
✅
type UserService = { readonly db: Database }

const svc: UserService = { db }

no-intersection-types — compose by field instead

Intersection types (A & B) are banned. Embed types as named fields.

❌
type AdminUser = User & { readonly role: 'admin' }
✅
type AdminUser = {
  readonly user: User
  readonly role: 'admin'
}
// access: admin.user.id

no-any / no-assertion / no-non-null / no-ts-comment

Type escape hatches are banned. No any, no as T (except as const), no !, no @ts-ignore. Use unknown and narrow explicitly.

Banned complex types

Conditional types, mapped types, template literal types, and infer are banned. These produce shapes that are hard to read at their definition site.

Banned utility types

Banned Reason Use instead
Partial<T> Produces optional properties (banned) Spell out with | null per field
Record<K, V> Produces index signature (banned) Map<K, V>
Readonly<T> Redundant — each property is already required to be readonly Mark properties directly
InstanceType, ConstructorParameters shot has no classes n/a

Kept: Pick, Omit, Exclude, Extract, NonNullable, Parameters, ReturnType, Awaited.

Null & undefined

no-undefined-type / no-optional-property / no-optional-parameter

shot has one nullable value: null. undefined cannot appear in user-authored type annotations. Optional properties (prop?: T) and optional parameters (x?: T) are banned — use explicit T | null.

❌
type User = { avatar?: string }
function f(x?: string): void { }
✅
type User = { readonly avatar: string | null }
function f(x: string | null): void { }

Runtime undefined still exists (e.g. arr[i] under noUncheckedIndexedAccess). Convert at the boundary: arr[i] ?? null. The language forbids writing undefined in types; it doesn't pretend the value can't appear.

Immutable by default

require-readonly-property / require-readonly-arrays

Every property in a user-authored object type must be readonly. Array type annotations must use readonly T[] — not T[] or Array<T>.

❌
type Config = { host: string; port: number }
const ids: number[] = []
✅
type Config = { readonly host: string; readonly port: number }
const ids: readonly number[] = []

Imports & exports

Import allowlist (ShotScript only)

Only these import specifiers are allowed in .shot files:

  • · shot:* — the standard library and shot packages
  • · bun:* — Bun built-in APIs
  • · Relative paths ending in .shot

No arbitrary third-party npm imports.

no-default-export

Default exports are banned. Named exports only — every export is addressable and tree-shakeable.

no-index-import

Importing from an index file or bare directory is banned. Import the specific file.

❌
import { add } from "./math/index.shot"
✅
import { add } from "./math/add.shot"

File naming

Name each file after the directory it lives in (Go package convention). For multi-file modules, name each file after what it exports. 

calculator/
  calculator.shot   ✅  matches directory
  index.shot        ❌  do not use

math/
  add.shot          ✅
  divide.shot       ✅

Control flow

no-ternary

Ternary expressions are banned. Use if/else or extract a named function.

❌
const label = isAdmin ? "Admin" : "User"
✅
function roleLabel(isAdmin: boolean): string {
  if (isAdmin === true) { return "Admin" }
  return "User"
}

no-for-in / no-do-while / no-labels

for...in is banned (use for...of Object.keys()). do...while is banned (use while). Labelled break/continue is banned (extract a function and return).

switch-no-fallthrough

Every switch case must end with break or return. Implicit fallthrough is banned.

no-and-shorthand

condition && doThing() for side effects is banned. Use if.

Operators

Banned Use instead
& | ^ ~ << >> Don't do bitwise
delete obj.x Build a new object without the key
"x" in obj Explicit property check or discriminated union
a, b (comma) Separate statements
arguments Rest params ...args
function* / yield for...of over iterables
eval() n/a
parseInt, parseFloat Number(str)
!!value Boolean(value)
==, != ===, !==

Strict tsconfig

shot build and shot run write a baked-in compilerOptions for every invocation. Users cannot relax it — the language defines its own tsconfig. 

"compilerOptions": {
  "strict": true,
  "noImplicitReturns": true,
  "noFallthroughCasesInSwitch": true,
  "noUnusedLocals": true,
  "noUnusedParameters": true,
  "noUncheckedIndexedAccess": true,
  "noPropertyAccessFromIndexSignature": true,
  "exactOptionalPropertyTypes": true,
  "allowUnreachableCode": false,
  "allowUnusedLabels": false,
  "noErrorTruncation": true,
  "verbatimModuleSyntax": true,
  "isolatedModules": true,
  "moduleDetection": "force"
}

noUncheckedIndexedAccess makes arr[i] return T | undefined — you must check. verbatimModuleSyntax requires type-only imports to say import type.
